# 정기 보험료 채권 생성 — 가상 상품 규칙

## 목적과 범위

초회 보험료로 활성화된 계약에 대해 매월 보험료 채권과 모의 자동출금 지시를 중복 없이 생성한다. 실제 출금 요청, 실결제, 법규 준수 판단은 포함하지 않는다.

## 생성 규칙

- 업무 날짜와 청구월 판단은 `Asia/Seoul`을 사용한다.
- 청구월은 항상 해당 월의 1일로 표현하며 미래 청구월은 생성하지 않는다.
- `ACTIVE`, `GRACE`, `CHANGE_SCHEDULED` 계약 중 청구월 이전 달에 활성화된 계약만 대상이다.
- `PENDING_INITIAL_PREMIUM`, `CANCELED`, `LAPSED`, `EXPIRED` 계약은 제외한다.
- 월 보험료와 통화는 최신 증권 버전의 불변 스냅샷에서 읽는다.
- 납부기일은 계약 활성화일의 일자를 기준으로 하되, 해당 월에 그 날짜가 없으면 월말로 조정한다.
- 기본 유예 종료일은 납부기일로부터 14일 뒤이며 설정으로 변경할 수 있다. 실제 실효 판단에는 미납 배치가 기록한 모의 독촉과 적용 유예 종료일을 사용한다.
- 하나의 `policy_id + billing_cycle`에는 채권 한 건과 자동출금 지시 한 건만 존재한다.

## 실행과 재개

- 실행 키는 유일하며 같은 키를 다른 청구월에 재사용하면 거부한다.
- 실행 시작 시 대상 계약과 보험료·납부기일을 고정한다.
- 20개 계약 단위로 채권 생성과 실행 체크포인트를 함께 커밋한다.
- 결과는 `CREATED`, `EXISTING`, `INELIGIBLE`로 구분하며 `대상 = 생성 + 기존 + 제외 + 남음`을 검증한다.
- 실패한 실행은 같은 실행 ID로 남은 대상부터 재개한다.
- 다른 실행이 같은 계약·청구월을 동시에 처리해도 DB 유일 제약과 계약 잠금으로 중복 채권을 만들지 않는다.

## 운영 경계

- `POST /api/v1/ops/premium-collections/billing/runs`: 실행 키, 청구월, 사유로 수동 실행한다.
- `POST /api/v1/ops/premium-collections/billing/runs/{id}/resume`: 실패 또는 진행 중 실행을 재개한다.
- `GET /api/v1/ops/premium-collections/billing/runs`: 최근 실행과 control total을 확인한다.
- 모든 경로는 관리자 권한이 필요하고 실행자·사유·시각을 별도 원장에 남긴다.
- `operations.premium-billing.scheduler-enabled`는 기본 `false`다. 명시적으로 활성화하면 매월 1일 00:05(KST)에 실행한다.

## 검증

- 월말 납부기일 보정과 증권 스냅샷 보험료
- 동일 실행 및 다른 경쟁 실행의 중복 방지
- 계약 상태와 활성화 월 대상 선별
- 실패 실행 재개와 감사 시도 원장
- 25개 계약에 대한 같은 실행 키 동시 요청
- 미래·비월초 청구월과 실행 키 충돌 거부
- 관리자 API 권한과 운영 화면 렌더링
