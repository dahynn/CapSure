## 적용 시 유의점

- 기존에 `JWT_SECRET`을 설정하지 않았다면 서버 재시작 후 다시 로그인해야 한다. 로컬 무작위 키는 프로세스 간 공유되지 않는다. 다중 인스턴스 운영에는 충분히 긴 별도 비밀키와 공유 세션/폐기 저장소가 필요하다.
- 기존 전문 원장과 이미 만들어진 환급 후보는 이 변경으로 자동 삭제·정정하지 않는다. 이번 검증은 격리 테스트 DB를 사용했다.
- 비인증 API 응답 계약이 403에서 401로 바뀌므로 외부 클라이언트·모니터도 이를 반영해야 한다.
- mock 프로필의 `/mock/**`는 합성 데이터용 공개 테스트 인터페이스다. 실제 개인 데이터 저장소를 연결하는 용도로 검증하지 않았다.

## 남은 개발·운영 범위

다음은 코드에서 확인한 잔여 항목으로, 기능 구현 완료와 별도다.

1. **배포 구성 정합성**: 현재 `Frontend/nginx.conf`에는 동일 출처 API 프록시가 없고 과거 도메인·인증서 경로가 고정되어 있다. `Infra/main/docker-compose.yml`의 backend 포트 8000과 main 프로필 8080도 맞춰야 한다. 배포 대상·도메인 선택 후 환경별 설정과 이미지 리허설이 필요하다.
2. **회원가입 인증**: `AuthService.signup`의 이메일·휴대폰 인증 강제가 주석 처리되어 있고 `SmsService.sendVerificationCode`는 메시지 구성만 수행한다. 실제 발송·요청 제한·인증 상태 일회 소비를 연결하기 전에는 운영 회원 인증으로 설명할 수 없다.
3. **세션·복구 다중 인스턴스**: refresh token/blacklist와 circuit 상태는 메모리다. 토큰 회전의 경쟁 요청 통제, 재시작·다중 서버 일관성은 추가 작업이다.
4. **이전 UI·집계**: `DashboardService.getSummary()`는 고정 값이다. `SessionTimer`의 `/auth/extend-session`도 백엔드 구현이 없다. 이들 과거 경로의 실제 사용 여부와 유지 범위를 정하고 연결해야 한다.
5. **외부 업무 연동**: Toss live 결제, 빌링키 자동결제, 취소·환불 실행, 운영 webhook, 실제 보험금 송금은 기존 합의상 제외다. 현재 환급 기능은 후보 원장 생성까지다.
6. **테스트 범위**: 이번 브라우저 검증은 합성 주문을 사용했다. 실제 Toss sandbox 흐름은 이전 PR에서 통과한 이력이지만 이번 수정 후 실제 PG를 통한 재검증은 별도다. 기존 전체 소스의 모든 입력·동시성·배포 조합을 전수 검증한 것은 아니다.
