# 보험료 수납·중복출금 보호 설계

## 문제

고객이 보험료를 즉시 납부했지만 기존 자동출금 지시가 이미 금융기관 처리 단계에 진입하면 두 거래가 모두 출금될 수 있다. 결제 주문 하나만으로는 보험료 채권, 출금 지시, 실제 수납 및 환급을 구분할 수 없다.

## 경계

| 책임 | 대표 상태 |
| --- | --- |
| 보험료 채권 | `DUE`, `GRACE`, `SETTLED`, `OVERPAID`, `LAPSED` |
| 출금 지시 | `SCHEDULED`, `SUBMITTED`, `CANCEL_REQUESTED`, `CANCELED`, `CAPTURED`, `FAILED`, `UNKNOWN` |
| 환급 건 | `PENDING`, `AUTO_REFUND_ELIGIBLE`, `MANUAL_REVIEW`, `REFUNDED` |

보험계약의 `ACTIVE`, `GRACE`, `LAPSED` 상태는 수납 상태와 별도다. 계약 상태 변경은 납입최고 및 유예기간을 처리하는 배치가 수행하며, 출금 실패 한 건만으로 즉시 변경하지 않는다.

## 선납 충돌 처리

1. 즉시 납부는 동일한 보험료 채권에 수납으로 반영한다.
2. 자동출금 지시가 `SCHEDULED`이면 취소한다.
3. `SUBMITTED`이면 취소 요청만 남기고 금융기관 결과를 기다린다.
4. 자동출금까지 `CAPTURED`되면 채권의 초과 수납을 계산한다.
5. 다음 영업일 대사 배치가 초과분에 대한 환급 건을 하나만 생성한다.
6. 환급 계좌와 금액이 규칙에 맞으면 자동 환급, 그렇지 않으면 운영 검토로 보낸다.

## 불변 조건

- 하나의 `policy_id + billing_cycle`에는 하나의 보험료 채권만 존재한다.
- 공급자 거래키와 수납 원장은 일대일이다.
- 동일 채권·동일 초과분에는 환급 건이 한 번만 생성된다.
- 환급 배치를 재실행해도 이미 환급된 금액을 다시 지급하지 않는다.
- 대사 기준식: `청구액 = 수납확정액 + 미수액 - 초과수납액`.

## 검증 시나리오

- 출금 전 선납: 자동출금 지시가 취소되고 수납은 한 건이다.
- 출금 마감 후 선납: 두 건이 수납되며 다음 영업일 환급 건이 한 건 생성된다.
- 동일한 출금 결과 웹훅 재전송: 수납·환급 건이 중복 생성되지 않는다.
- 납입최고 기간 종료: 계약 효력 상태만 변경하고, 미확정 출금 건은 대사 대상에 남긴다.
