# 청구 증빙 접근 감사

## 목적

`GET /api/v1/claims/{claimId}`가 반환하는 청구·증빙 조회를 개인정보 원문 없이 추적한다. 소유자 조회와 소유자가 아닌 조회 시도를 모두 남겨 보험금 청구 정보의 오남용 조사 근거를 만든다.

## 기록 범위

- 한 HTTP 조회를 `access_request_id` 하나로 묶는다.
- 항상 청구 ID 대상 이벤트 한 건을 남긴다.
- 허용된 조회는 실제 반환된 증빙 ID마다 대상 이벤트를 추가한다.
- 소유자가 아닌 조회는 기존과 동일하게 404로 숨기고 `DENIED_NOT_FOUND` 청구 이벤트만 남긴다.
- 행위는 `CLAIM_DETAIL_READ`, 결과는 `ALLOWED` 또는 `DENIED_NOT_FOUND`만 허용한다.

감사 테이블에는 합성 참조, 체크섬, 증빙 메타데이터, 진단 내용, 응답 본문을 저장하는 열이 없다. 사용자·청구·증빙의 내부 숫자 식별자와 발생 시각만 저장한다.

## 무결성과 실패 원칙

- 애플리케이션의 수정·삭제를 DB 트리거가 거부하는 append-only 테이블이다.
- 청구 이벤트와 증빙 이벤트를 별도 `REQUIRES_NEW` 트랜잭션으로 함께 저장한다.
- 감사 저장이 실패하면 청구 상세 응답도 실패시켜 기록 없는 민감 조회를 허용하지 않는다.
- 사용자·청구가 이후 삭제되더라도 조사 식별자를 보존하기 위해 감사 테이블에는 삭제 전파 외래키를 두지 않는다.

## 현재 한계

- 로그인 이전의 401 요청은 식별 가능한 행위자가 없어 이 감사 테이블에 기록하지 않는다.
- 관리자용 조회 화면, 보존 기간, 별도 WORM 저장소 연계는 포함하지 않는다.
- DB 소유자나 슈퍼유저의 테이블 제거까지 막는 외부 불변 저장소는 아니다.
